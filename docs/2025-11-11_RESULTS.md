# Results: 2025-11-11
## Experiment 2L Revised - Critical Overfitting Discovery

## Executive Summary

Revised Experiment 2L revealed **severe overfitting** when training on a single permutation and validating on other individual permutations. The model achieves r=0.98 on the training permutation (perm 0) but only r=0.71 on validation permutations (11-20).

**Critical finding**: The original Experiment 2L's r=0.9076 result was **artificially inflated** by validating against the mean of 10 permutations rather than individual permutations. This masked severe generalization failure.

## Background

**Original Experiment 2L (2025-11-05):**
- Training: Perm 1
- Validation: Mean of perms 11-20
- Result: r=0.9076 (appeared to be a breakthrough)

**Revised Experiment 2L (2025-11-11):**
- Training: Perm 0 (consistent usage)
- Validation: Individual perms 11-20 (not averaged)
- Purpose: More efficient (eliminate perm 1) and more informative (see variance)

## Root Cause Analysis

### Why Does Training on Single Permutation Fail?

**Hypothesis 1: Intermediate structure varies across permutations**

From earlier analysis (check_intermediate_preservation.py):
- Intermediate counts have r=0.85-0.89 correlation across permutations
- Only 14% of pairs have identical intermediate counts
- Mean difference: 3-3.5 intermediates per pair

**When training on perm 0:**
- Features extracted for perm 0's specific intermediates
- Example: pair (C, PW) has intermediates {G1, G5, G10} in perm 0
- In perm 11, same pair might have {G2, G5, G8}
- sum_CbGiG aggregates over different genes with different degrees
- Model learns perm 0's specific degree distribution, not general pattern

**Hypothesis 2: Validating on mean reduces variance**

Original validation approach:
```python
y_val = mean([counts_perm_i for i in range(11,21)])
r = corr(predictions, y_val)
```

This averages out permutation-specific noise:
- Each perm has unique intermediate sets
- Mean smooths these differences
- Predictions from perm 0 features correlate better with smoothed target
- Result: artificially high r=0.91

**Hypothesis 3: Features are permutation-specific**

Features depend on which intermediates are identified:
- sum_CbGiG = sum(pred_CbGiG[deg_C, deg_G] for G in intermediates_perm0)
- Different perms have different intermediate sets
- Same feature value in perm 0 vs perm 11 doesn't correspond to same expected count

### Why Did Original Experiment Show r=0.9076?

The original experiment's high correlation was achieved by:
1. Training on perm 1 targets
2. **Validating on mean(perms 11-20)** - the key difference

The mean of 10 permutations:
- Is more stable than any individual permutation
- Reduces variance from permutation-specific topology
- Makes predictions from perm 1 features appear more accurate

But this doesn't reflect real-world use: when we generate 1 permutation for a new graph, we get ONE realization, not the mean of 10.

## Implications

### For Null Model Development

**Compositional approaches (Experiments 2H-2J) were correctly rejected:**
- Those showed r=0.78-0.80 ceiling
- But they were also using mean(perms 11-20) for validation
- True generalization might be even worse (r~0.60?)

**Aggregation approach (Experiment 2L) does NOT work as claimed:**
- Original r=0.9076 was measurement artifact
- True cross-permutation generalization: r~0.71
- Still better than composition (r~0.60), but far from r>0.95 needed

### For Experiment Design

**Critical lesson: Validate on individual permutations, not means**

Validating on mean(perms) masks generalization failures by:
1. Reducing variance from permutation-specific topology
2. Creating an unrealistically stable target
3. Inflating correlation metrics

**Proper validation should:**
- Train on one or more permutations
- Validate on completely separate individual permutations
- Report mean and std of validation metrics
- Check for overfitting (training r >> validation r)

### For Previous Work (November 3)

November 3 work showed r>0.95 for degree-based models with 1 permutation. But those also validated on mean(perms 6-20).

**Need to re-evaluate:**

## What Went Wrong with Aggregation Approach?

The 25-feature aggregation was supposed to capture distributional information beyond simple composition. But:

**Feature extraction depends on topology:**
- Intermediates identified from perm 0 edges
- Different perms have different intermediates
- Features encode perm 0's specific structure
- Don't generalize to other permutations

**The feature engineering was permutation-specific:**
- sum_CbGiG sums predictions for perm 0's intermediates
- In perm 11, different intermediates exist
- Same sum value doesn't correspond to same pathway count
- Model memorizes perm 0 patterns instead of learning degree-based rules

## Possible Solutions

### Option 1: Train on Multiple Permutations

**Approach:**
```python
# Train on mean of perms 0-9
y_train = mean([counts_perm_i for i in range(10)])

# Validate on individual perms 11-20
for perm in range(11, 21):
    y_val = counts_perm
    r = corr(predictions, y_val)
```

**Expected outcome:**
- Training on mean might learn more general patterns
- But features still from perm 0 topology
- Unlikely to solve fundamental issue

### Option 2: Degree-Only Features (No Topology)

**Approach:**
Extract features that don't depend on which intermediates exist:
- deg_C, deg_PW (endpoint degrees)
- deg_C × deg_PW, deg_C², deg_PW² (polynomial terms)
- NO sums over intermediates
- NO topology-based intermediate identification

**Expected outcome:**
- Lower training performance (can't memorize perm 0)
- Better generalization (permutation-invariant features)
- May achieve r~0.80-0.85 (comparable to November 3 degree models)

### Option 3: Expected Intermediate Features

**Approach:**
Instead of summing over actual intermediates in perm 0, compute expected features:
```python
# For all genes (not just perm 0 intermediates):
expected_sum_CbGiG = sum(
    P(CbGiG exists | deg_C, deg_G) × pred_CbGiG(deg_C, deg_G)
    for all genes G
)
```

**Challenge:**
- Requires computing over all genes (expensive)
- Essentially the compositional approach
- Already know that fails (r~0.78)

### Option 4: Accept Enumeration Necessity

**Approach:**
- For each query graph, generate 5-10 permutations
- Enumerate pathways in each permutation
- Use empirical counts for null distribution
- No prediction needed

**Advantages:**
- Exact, no approximation error
- Proven to work

**Disadvantages:**
- Computational cost
- But may be unavoidable if prediction fails

## Conclusions

### Main Finding

**Experiment 2L's r=0.9076 "breakthrough" was a measurement artifact.** True cross-permutation generalization is r~0.71, far below the r>0.95 threshold needed for null model applications.

### Root Cause

1. **Topology-dependent features**: Intermediate identification from perm 0 creates permutation-specific features
2. **Validation on means**: Averaging perms 11-20 inflated correlation by ~0.20 points
3. **Severe overfitting**: r=0.98 on training perm, r=0.71 on validation perms

### Implications

The aggregation approach does NOT solve the compositional null model problem:
- Compositional models: r~0.78 (validated on mean)
- Aggregation models: r~0.71 (validated on individual)
- Degree-only models: Unknown (need re-validation)

### Path Forward

**Most promising approach:** Re-validate November 3 degree-based models
- If those hold up (r>0.90 on individual perms): Use degree-only features
- If those also fail: Accept enumeration for null distribution estimation

**Abandoned approach:** Topology-dependent aggregation features
- Fundamentally permutation-specific
- Cannot generalize across permutations
- Training performance misleading
