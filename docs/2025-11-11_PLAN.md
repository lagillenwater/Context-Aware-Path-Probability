# Work Plan: 2025-11-11

## Context

Previous session (2025-11-05) achieved r=0.9076 for predicting 3-edge pathway counts using non-linear aggregation of 2-hop predictions (Experiment 2L). However, the experimental design had several inefficiencies:

1. Used perm 1 for training but perm 0 for topology (inconsistent)
2. Validated against mean(perms 11-20) rather than individual permutations
3. Required computing 11 permutations (0, 1, and 11-20)

Today's goals are to fix these issues and prepare for scaling tests.

## Priority 1: Re-run Experiment 2L with Improved Design

### Motivation

The current design is inefficient for large-scale deployment. For new graphs, we want to compute only 1-2 permutations total, not 11.

### Revised Design

**Permutation usage:**
- Perm 0: Topology, degrees, 2-hop model training, 3-hop training target
- Perms 11-20: Individual validation (not averaged)
- Total permutations needed: 11 (down from original, and perm 1 eliminated)

**Evaluation approach:**
- Train once on perm 0
- Predict once for test pairs
- Evaluate predictions against each of perms 11-20 separately
- Report: mean r, std r, min/max r, mean MAE, std MAE

**Expected benefits:**
1. Cleaner logic (no averaging counts before evaluation)
2. More informative (see variance across permutations)
3. Consistent permutation usage (perm 0 for all training)
4. Aligns with November 3 approach that used perm 0 for training

### Implementation

Create `test_src/test_nonlinear_aggregation_exp2l_revised.py` that:
- Uses perm 0 for both topology AND training targets
- Validates against individual perms 11-20
- Reports aggregated statistics with confidence intervals
- Includes feature importance from best model

### Expected Outcomes

**Hypothesis 1**: Performance will be similar to original (r~0.90)
- Using perm 0 vs perm 1 shouldn't matter much
- More consistent approach may slightly improve results

**Hypothesis 2**: Variance across permutations will be low (std < 0.05)
- If model truly learns degree-based patterns, should generalize consistently
- High variance would indicate permutation-specific overfitting

**Success criteria:**
- Mean r > 0.85 (comparable to original r=0.9076)
- Std r < 0.10 (reasonably consistent)
- Min r > 0.75 (no catastrophic failures on any permutation)

## Priority 2: Feature Importance and Reduction Analysis

### Motivation

Original Experiment 2L showed top 5 features account for 77% of importance:
1. sum_CbGiG: 44.3%
2. sum_GiGpPW: 13.8%
3. deg_C: 9.3%
4. deg_PW: 5.6%
5. mean_pred_CbGiG: 5.1%

Can we reduce from 25 features to 10-12 without losing performance?

### Approach

**Test reduced feature sets:**
1. Top 5 features only
2. Top 10 features
3. Top 15 features
4. All 25 features (baseline)

For each subset:
- Retrain Linear, RandomForest, GradientBoosting models
- Evaluate on perms 11-20
- Compare to full 25-feature baseline

### Expected Outcome

If performance plateaus at 10-15 features, this reduces computation by ~40-60% with no accuracy loss.

## Priority 3: Test Generalization to Other 3-Edge Metapaths

### Motivation

Current results only validated on CbGiGpPW. Need to confirm approach generalizes to other 3-edge metapaths with different edge types and node types.

### Candidate Metapaths

Test on 3-5 additional 3-edge metapaths:

1. **CtDaG** (Compound-treats-Disease-associates-Gene)
   - Medical relevance pathway
   - Different edge semantics
   - Bottleneck: CtD (755 edges) - small but not sparse

2. **CrCbG** (Compound-resembles-Compound-binds-Gene)
   - Tests compound similarity relationships
   - Intermediate is same type as source
   - Bottleneck: CbG (11,571 edges) - large

3. **DaGiGpPW** (Disease-associates-Gene-interacts-Gene-participates-Pathway)
   - Can reuse GiG and GpPW 2-hop models from Priority 1
   - Tests starting from Disease instead of Compound
   - Bottleneck: DaG (12,623 edges) - large

4. **CbGaD** (Compound-binds-Gene-associates-Disease)
   - Tested successfully in November 3 work for degree models
   - Reverse direction of DaG
   - Bottleneck: CbG (11,571 edges) - large

5. **GiGpPWpG** (Gene-interacts-Gene-participates-Pathway-participates-Gene)
   - Both endpoints are genes
   - Pathways as intermediates
   - Different structural pattern

### Implementation

For each metapath:
1. Load perm 0 topology and identify required 2-hop models
2. Train or reuse 2-hop models (CbGiG, GiGpPW already trained)
3. Sample 10,000 pairs (stratified: 50% nonzero, 50% random)
4. Extract 25 aggregation features
5. Train on perm 0, validate on perms 11-20 individually
6. Record mean r, std r, feature importance

### Success Criteria

**Minimum success**: 3 of 5 metapaths achieve mean r > 0.85
**Good success**: 4 of 5 metapaths achieve mean r > 0.85
**Ideal success**: All 5 metapaths achieve mean r > 0.90

If any metapath fails (r < 0.80), investigate:
- Is it sparse? (like CpDaG in November 3)
- Are intermediate counts poorly preserved?
- Do 2-hop models work well for those edge types?

## Priority 4: Test Hierarchical Scaling to 4-Edge Paths

### Motivation

Validate that approach scales to longer paths without severe error accumulation.

### Test Case

**CbGiGpPWpG** (Compound-binds-Gene-interacts-Gene-participates-Pathway-participates-Gene)
- Natural extension of CbGiGpPW
- Can reuse trained models from Priority 1
- 4 edges = 3 2-hop models needed

### Hierarchical Implementation

**Phase 1: Prepare 2-hop models**
- CbGiG model (already trained in Priority 1)
- GiGpPW model (already trained in Priority 1)
- PWpG model (need to train)

**Phase 2: Extract 4-hop features**

For each Compound-Gene pair (C, G_target):
1. Identify intermediate pathways: PW where both CbGiGpPW[C, PW] > 0 and PWpG[PW, G_target] > 0
2. For each intermediate PW:
   - Use aggregation features from CbGiGpPW model (not composition)
   - Get PWpG prediction from 2-hop model
   - Compute interaction terms

3. Extract 25+ aggregation features:
   - Sum, mean, std, max, min of 3-hop predictions (from aggregation model)
   - Sum, mean, std, max, min of PWpG predictions (from 2-hop model)
   - Count of intermediate pathways
   - Endpoint degrees (deg_C, deg_G_target)

**Phase 3: Train and validate**
- Train on perm 0 4-hop counts
- Validate on perms 11-20 individually

### Key Question

Does using the 3-hop aggregation model (r~0.90) instead of composition reduce error accumulation?

**Comparison test**:
- Approach A: Use 3-hop aggregation model predictions as features
- Approach B: Use 2-hop × 2-hop × 2-hop composition directly
- Compare: Does A outperform B?

### Success Criteria

**Minimum**: r > 0.75 (acceptable degradation from 3-edge)
**Good**: r > 0.80 (manageable error accumulation)
**Ideal**: r > 0.85 (minimal degradation)

If r < 0.75, this indicates hierarchical approach has too much error accumulation for 4+ edge paths.

## Priority 5: Prepare HPC Scaling Strategy

### Motivation

With HPC available, can parallelize testing across:
- Multiple metapaths
- Multiple path lengths
- Hyperparameter searches

### HPC Task Design

**Job array structure:**
```bash
#SBATCH --array=1-100
# Each job tests one metapath
METAPATHS=(CbGiGpPW CtDaG CrCbG DaGiGpPW ...)
METAPATH=${METAPATHS[$SLURM_ARRAY_TASK_ID]}
python test_src/test_metapath_aggregation.py --metapath $METAPATH
```

**Parallelization opportunities:**
1. 3-edge metapath testing (Priority 3): 5 jobs in parallel
2. Feature reduction testing (Priority 2): 4 jobs in parallel
3. 4-edge path testing (Priority 4): 10-20 metapaths in parallel
4. Neural network hyperparameter search: 50-100 jobs in parallel

### Shared Model Repository

To avoid retraining 2-hop models:
```
results/2hop_models/
  CbGiG_perm0.pkl
  GiGpPW_perm0.pkl
  CtD_perm0.pkl
  ...
```

Each job loads pre-trained 2-hop models and only trains 3-hop aggregation model.

### Resource Estimation

Per 3-edge metapath job:
- Time: ~20 minutes (feature extraction + model training)
- Memory: ~8GB
- CPU: 4 cores (for RandomForest parallelization)

For 50 metapath jobs: ~20 minutes wall time with sufficient HPC resources.

## Expected Challenges

1. **Computational time**: Testing 5 metapaths sequentially takes 2-3 hours. Solution: Use HPC job array.

2. **Memory for 4-edge paths**: May need to store intermediate predictions. Solution: Compute on-demand rather than caching.

3. **Sparse metapaths**: Some 3-edge metapaths may have very few examples. Solution: Skip if < 1000 pairs available.

4. **2-hop model availability**: May need to train many new 2-hop models. Solution: Check which exist, train missing ones in batch.
