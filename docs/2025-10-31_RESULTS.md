- Maximum absolute error: 0.41

**Strategies to Overcome Underprediction Bias**:

1. Bias Correction Layer:
   - Add learned bias term to model output
   - Post-training calibration on validation set
   - Apply multiplicative or additive correction factor

2. Modified Loss Function:
   - Use asymmetric loss that penalizes underestimation more heavily
   - Quantile regression targeting median or higher percentiles
   - Weighted MSE with higher weights for underestimated bins

3. Feature Engineering:
   - Add graph-level statistics (edge density, clustering coefficient)
   - Include ratios of original vs expected edge counts
   - Incorporate higher-order network motifs

4. Ensemble Methods:
   - Combine predictions from original graph and multiple permutations
   - Train separate models on permutations and average predictions
   - Use stacking with bias-corrected meta-model

5. Direct Permutation Training:
   - Train on subset of permutations instead of original graph
   - Use permutation averages as targets (current approach)
   - Augment training with permutation samples

6. Output Transformation:
   - Train model to predict log-transformed counts
   - Apply power transformation to reduce scale compression
   - Use quantile normalization of predictions

Recommended next step: Test bias correction layer (Strategy 1) as it is
simple, interpretable, and can be applied post-hoc without retraining

**Key Findings**:

   - All feature sets C-F improve over baseline A
   - Set E provides best overall performance
   - Polynomial terms capture non-linear degree-pathway relationships

2. **Bias reduction is dramatic**:
   - Baseline bias: -0.0310 (3.1% underestimation)
   - Set E bias: -0.0177 (1.8% underestimation)

3. **Log transforms (Set B) provide minimal benefit**:
   - Actually slightly worse than baseline
   - Suggests linear/polynomial features are more appropriate than log-scale

4. **Summary statistics (Set C) help moderately**:
   - Captures global properties of intermediate signature
   - Note: Sensitive to random seed (failed with seed 789, works with seed 123)

5. **Neighbor context (Set D) adds signal**:
   - Node counts and edge densities provide additional information
   - Moderate improvement over Set C

6. **Polynomial terms (Set E) are most effective**:
   - Squared and sqrt terms capture threshold effects
   - Likely model saturation behavior in pathway formation

   - All models train in < 7 seconds
   - All models infer in < 1 millisecond
   - Feature engineering adds minimal overhead

**Interpretation**:

The success of polynomial features (Set E) suggests that pathway formation exhibits non-linear behavior with respect to node degrees:
- **Squared terms** may capture super-linear accumulation at high degrees
- **Square root terms** may capture sub-linear saturation at low degrees
- Together they provide flexible non-linear modeling without overfitting

The underprediction bias (-2.8% baseline → -1.8% Set E) is substantially reduced but not eliminated. The remaining bias is likely structural:
- Original graph has biological constraints not present in permutations
- Permutations have 60% higher mean pathway counts (Phase 0 finding)
- Complete bias elimination may require:
  - Post-hoc calibration
  - Modified loss functions
  - Training on permutation ensembles

## Phase 5b: Degree-Aware Bias Correction

**Status**: COMPLETE
**Goal**: Address fundamental limitation of offset correction (requires validation data) with degree-aware correction using permutation 0
**Prerequisite**: Phase 5 complete

### The Fundamental Problem with Offset Correction

Phase 5 showed that simple offset correction eliminates bias perfectly, but has a critical limitation: **it requires access to validation data**. The offset is calculated as `mean(y_pred - y_true)` where `y_true` are permutation average pathway counts. But this defeats the purpose: if we already have permutation averages, we don't need predictions.

**Production Scenario**:
For new node pairs not in training data, we need to predict permutation average pathway counts without having those permutation averages available.

**Original Approach**:
1. Train on original graph → predict original graph counts
2. Validate on permutation averages → measure bias
3. Apply offset correction → eliminate bias

**Problem**: Step 3 requires knowing permutation averages (validation data), which aren't available for new predictions.

### The Solution: Learn Correction from Permutation 0

**Key Insight**: Instead of training on original graph to predict original graph counts, we can learn the systematic transformation from original graph to permutation space using a single permutation.

**Two-Stage Approach**:
1. **Stage 1**: Train model on original graph to predict original graph pathway counts
2. **Stage 2**: Learn correction function using (original graph, permutation 0) paired data
3. **Inference**: Apply learned correction to predictions for new data

**Why This Works**:
- Permutation 0 is highly representative of permutation average (Phase 0b: r = 0.9967)
- Correction is learned as function of degree features AND predicted pathway count
- Correction generalizes to all permutations without requiring validation data
- No access to validation data needed at inference time

### Degree-Aware Correction Model

**Implementation**: `src/degree_aware_correction.py`

**DegreeAwareCorrectionModel**: Two-stage model

**Stage 1**: Base model predicts original graph counts
```python
base_model = LinearRegression()
base_model.fit(X, y_original)
y_pred = base_model.predict(X)
```

**Stage 2**: Correction model learns from (original, perm 0) differences
```python
correction_model = LinearRegression()
correction_target = y_perm0 - y_pred
correction_features = extract_correction_features(X, y_pred)
correction_model.fit(correction_features, correction_target)
```

**Correction Features** (15 features with interactions):
- Degree features (7): source_bin, target_bin, source × target, source², target², sqrt(source), sqrt(target)
- Prediction features (3): y_pred, y_pred², log(y_pred)
- Interaction terms (5): y_pred × source_bin, y_pred × target_bin, y_pred × (source × target), sqrt(y_pred) × source_bin, sqrt(y_pred) × target_bin

**Inference**: `y_corrected = y_pred + correction_model.predict(correction_features)`

**Key Advantage**: Correction depends on both degrees AND pathway count magnitude, addressing heteroscedasticity.

### Implications for Production

**Recommended Model**: Two-Stage Linear Regression with Degree-Aware Correction

**Training Protocol**:
1. Extract features from original graph (Feature Set E): X, y_original
2. Compute pathway counts from permutation 0: y_perm0
3. Fit base model: `base_model = LinearRegression().fit(X, y_original)`
4. Get base predictions: `y_pred = base_model.predict(X)`
5. Extract correction features (15 features): degree terms + y_pred + interactions
6. Fit correction model: `correction_model = LinearRegression().fit(correction_features, y_perm0 - y_pred)`

**Inference Protocol**:
1. For new node pair, extract features from original graph: X_new
2. Predict with base model: `y_pred = base_model.predict(X_new)`
3. Extract correction features: `correction_features = [degrees, y_pred, interactions]`
4. Apply correction: `y_final = y_pred + correction_model.predict(correction_features)`

**Advantages**:
- Achieves r > 0.99 on most metapaths (near-perfect null estimation)
- No validation data required (only permutation 0, computed once)
- Addresses heteroscedasticity (bias varies with pathway count and degrees)
- Dramatically better than baseline (r: +1.1% to +4.3%, RMSE: -49% to -74%)
- Fast training (< 0.1s per metapath)
- Simple implementation (two LinearRegression models, no hyperparameters)
- Correction is interpretable (degree × prediction interactions)

**Computational Requirements**:
- One-time: Compute permutation 0 for correction training
- Per metapath: Train two LinearRegression models (230 features total)
- Inference: Two linear predictions per node pair

### Implementation Notes

**Two-Stage Training**:
- Stage 1 trains on original graph to learn degree → pathway mapping
- Stage 2 learns correction from (original, perm 0) differences
- Correction features combine degree bins, predictions, and interactions

**Feature Engineering**:
- Base features: source_bin, target_bin, products, polynomials
- Prediction features: y_pred, y_pred², log(y_pred)
- Interaction features: y_pred × source, y_pred × target, y_pred × (source × target)

**Model Selection**:
- Use DegreeAware for most cases (simple, no hyperparameters)
- Use Multiplicative for very sparse metapaths (< 15 bins)
- Both achieve r > 0.99 in practice
