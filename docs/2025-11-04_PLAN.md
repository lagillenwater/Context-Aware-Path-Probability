## Context and Motivation

### The Computational Crisis

Our current pipeline can analyze pathways of length 2-3 efficiently and length 4 with significant effort (approximately 6 minutes per metapath using optimized sparse matrix operations). However, pathways of length 5 or greater are effectively infeasible with direct counting methods. This creates a severe limitation because many biologically and clinically relevant pathways require longer paths. For example, understanding how a compound might treat a disease through multiple intermediate genes and biological processes often requires paths of length 5-7.

The computational cost grows exponentially with path length. For a path of length L through a graph with average degree d, the naive cost is O(d^L). Even with sparse matrix optimizations that exploit the sparsity of biological networks, we still face exponential growth. Yesterday's optimization reduced a length-4 path computation from indefinite hanging to 6 minutes, but this represents the practical limit of direct counting approaches.

### Why Edge Multiplication Failed

In notebook 17, we tested whether we could predict pathway counts by multiplying edge probabilities: P(A→B→C→D) ≈ P(A→B) × P(B→C) × P(C→D). This approach failed catastrophically with a correlation of only r=0.35. The failure occurred because edge multiplication assumes independence between edges, ignoring the critical fact that edges share intermediate nodes whose degrees create strong dependencies.

For example, if node B has high degree, then both P(A→B) and P(B→C) are influenced by this shared factor. Simply multiplying these probabilities double-counts the effect of B's degree. Additionally, the presence of an A→B edge may be correlated with the presence of a B→C edge through biological mechanisms, network structure, or degree correlations that the simple multiplication model cannot capture.

### The Path-Level Hypothesis

Today's central hypothesis is fundamentally different from the failed edge multiplication approach. Instead of multiplying edge probabilities, we propose predicting long pathway counts from shorter pathway counts using linear regression with rich feature sets. The key insight is that actual pathway counts (not probabilities) might be compositional when we include appropriate features.

Consider predicting Count(A→B→C→D) from features including Count(A→B), Count(B→C), Count(C→D), Count(A→B→C), Count(B→C→D), all relevant node degrees, and interaction terms like Count(A→B→C) × Count(B→C→D). This approach has several advantages over edge multiplication. First, it uses observed pathway counts rather than probabilities, which may have better mathematical properties. Second, it can capture degree effects explicitly through features. Third, interaction terms can model shared node effects. Fourth, we use a trained model that can learn the correct combination weights rather than assuming simple multiplication.

The critical question is whether this approach can achieve r > 0.95, which would indicate that pathway counts are predictable enough to replace direct counting for long paths.

## Priority 1: Testing the Hierarchical Path Prediction Hypothesis

### Experimental Design Philosophy

We will test the hierarchical prediction hypothesis through a carefully designed series of experiments that progress from simple to complex. Each experiment builds on the previous one and tests a specific aspect of the hypothesis. If any experiment fails, we can diagnose why and determine whether the approach is fundamentally flawed or simply needs refinement.

The experiments are designed to answer these specific questions:
1. Can we predict length-2 paths from length-1 edge counts? (This should be nearly trivial and serves as a sanity check)
2. Can we predict length-3 paths from length-2 subpath counts? (This is the first real test of composition)
3. Can we predict length-4 paths from length-2 and length-3 subpath counts? (This tests recursive composition)
4. Does the approach generalize across different metapath types? (This tests whether findings are universal or metapath-specific)

### Experiment 1: Length-2 from Length-1 (Sanity Check)

For this experiment, we will use the CbGaD metapath (Compound→Gene→Disease) as our test case because it has well-understood properties from yesterday's analysis. The metapath consists of two edges: CbG (Compound binds Gene) with 11,571 edges, and DaG (Disease associates Gene) with 12,623 edges when reversed to GaD.

The prediction task is to estimate the number of length-2 paths between each compound-disease pair. Our features will include the total number of CbG edges from each compound (essentially the compound's degree in the CbG network), the total number of GaD edges to each disease (the disease's degree in the GaD network), the compound's degree, the disease's degree, and interaction terms such as the product of these counts.

This experiment should succeed with very high correlation (r > 0.99) because counting length-2 paths through matrix multiplication is mathematically equivalent to summing the products of edge counts. If this experiment fails, it indicates a problem with our experimental setup or data handling rather than a fundamental limitation of the approach.

### Experiment 2: Length-3 from Length-2 (Core Test)

This experiment represents the first genuine test of the compositional hypothesis. We will select a length-3 metapath such as CbGiGpPW (Compound→Gene→Gene→Pathway). To predict the number of length-3 paths between each compound-pathway pair, we will use features derived from all possible length-2 subpaths.

Specifically, our features will include Count(C→G→G) for each compound, Count(G→G→PW) for each pathway, the individual edge counts in each direction, all relevant node degrees (compound degree, gene degrees, pathway degree), and crucially, interaction terms that capture relationships between the subpaths. The interaction term Count(C→G→G) × Count(G→G→PW) is particularly important because it should correlate with the shared intermediate gene's connectivity properties.

Success in this experiment (r > 0.95) would provide strong evidence that pathway counts are compositional at the path level. It would suggest that the information contained in shorter paths, combined with degree features, is sufficient to predict longer path counts without explicitly enumerating all possible paths. This would be transformative because it means we can compute short paths (which is fast) and predict long paths (which is instantaneous after model training).

Partial success (0.8 < r < 0.95) would still be valuable, as it might indicate that the approach works approximately and could be refined with better features or non-linear models. Failure (r < 0.8) would suggest that pathway counts have complex dependencies that cannot be captured by linear combinations of subpath counts.

### Experiment 3: Length-4 from Length-2 and Length-3 (Recursion Test)

If Experiment 2 succeeds, this experiment tests whether the compositional property extends recursively to longer paths. We will attempt to predict length-4 path counts using all length-2 and length-3 subpath counts as features, along with degrees and interactions.

The critical question here is whether composition compounds: if we can predict length-3 from length-2, and length-4 from length-3, can we continue this indefinitely? Or do errors accumulate such that predictions become unreliable after a few recursion steps?

This experiment also tests computational viability. If successful, we would compute all length-2 paths (fast), all length-3 paths (moderate cost), and then predict all length-4+ paths (virtually free). This would provide massive computational savings compared to direct counting.

### Feature Engineering Strategy

Our feature sets will be carefully designed to capture different aspects of path composition. The basic features include raw subpath counts (e.g., Count(A→B), Count(B→C)) which provide direct information about connectivity. Degree features (deg_A, deg_B, deg_C, deg_A², deg_B²) capture node-level properties that influence path formation. Interaction terms (Count(A→B) × Count(B→C), deg_A × deg_B) model dependencies between subpaths and degrees.

We will also test whether we need to include all possible features or whether a subset is sufficient. Dimensionality reduction through feature selection could improve model generalization and reduce computation time. We will examine the trained model coefficients to understand which features are most important, providing insights into the mechanisms of path composition in biological networks.

### Decision Criteria and Next Steps

The outcomes of these experiments will determine our path forward. If all three experiments succeed (r > 0.95), we will immediately implement a hierarchical path counting system and deploy it for anomaly detection across all metapaths. We will formalize the approach into a reusable module and validate it on diverse metapath types.

If Experiment 2 or 3 achieves partial success (0.8 < r < 0.95), we will investigate whether non-linear models (random forests or neural networks) can improve performance. We will also analyze residuals to understand what patterns the linear model misses. Even with r = 0.9, the approach might be valuable for generating approximate counts or filtering candidates for detailed analysis.

If the experiments fail (r < 0.8), we will need to understand why. We will examine whether certain types of paths (dense vs. sparse, symmetric vs. directed) are more predictable than others. We will also consider whether the failure is due to biological mechanisms (e.g., pathway redundancy, evolutionary constraints) or network properties (e.g., clustering, modularity). Understanding the failure mode will guide us toward alternative approaches such as sampling-based estimation or hub-based sparse path representations.

## Priority 2: Comprehensive Bottleneck Analysis

### The Path Counting Bottleneck

The dominant computational bottleneck in our pipeline is path counting for paths longer than 3 edges. This bottleneck manifests in multiple ways and has cascading effects throughout the analysis workflow. Understanding its exact nature and severity is essential for designing effective solutions.

Direct path counting using sparse matrix multiplication has cost O(nnz_1 × nnz_2 × ... × nnz_L) where nnz_i is the number of non-zero entries in edge matrix i and L is the path length. For dense edges like GiG with 294,328 edges, even a length-3 path requires on the order of 294k³ ≈ 2.5×10^16 operations in the worst case. Sparse matrix implementations reduce this by exploiting the sparsity pattern, but the cost still grows exponentially with path length.

Yesterday's optimization work demonstrated both the success and limits of sparse matrix approaches. We reduced length-4 path counting from indefinite hanging (the original nested-loop implementation failed to complete even after hours) to approximately 6 minutes by rewriting the computation using sparse matrix multiplication. This represents a significant achievement, but 6 minutes per metapath-permutation combination is still expensive when we need to analyze dozens of metapaths. More critically, extrapolating this trend suggests that length-5 paths would take hours and length-6+ would be infeasible.

The exponential growth has severe implications for our research goals. Many biologically interesting pathways require long paths. For example, understanding how metformin (a diabetes drug) might affect cardiovascular disease through gene regulation, protein interactions, and pathway activation could require paths of length 5-7. Our current methods cannot reach these pathways, creating a fundamental limitation in the types of biological questions we can address.

### Matrix Operations on Large Graphs

While not as severe as the path counting bottleneck, operations on large graphs present significant challenges for interactive analysis and iteration speed. The Gene-Gene interaction network has 20,945 nodes, creating a potential matrix size of 20,945 × 20,945 ≈ 438 million entries. Even stored in sparse format, this matrix requires substantial memory and computation time for operations.

Each sparse matrix multiplication on matrices of this scale takes seconds, which accumulates quickly when we perform many operations. For example, computing degree distributions, extracting specific node pairs, or performing matrix-vector products all incur non-trivial cost at this scale. This impacts our ability to rapidly iterate during development and makes interactive exploration of results difficult.

However, this bottleneck is manageable and does not fundamentally limit our approach. We can mitigate it through caching, parallel computation, and careful algorithm design. The edge sparsity analysis completed this morning processed all 24 edge types in under a minute, demonstrating that well-optimized code can handle these graph sizes efficiently.

### Permutation Storage: A Solved Problem

Originally, we faced a significant permutation storage bottleneck. With 200 permutations per edge type and 24 edge types, we needed to store and process 4,800 permutation files totaling approximately 50 GB. Loading permutations from disk was slow, and the storage requirements were substantial.

Yesterday's breakthrough in minimal permutation requirements effectively solved this bottleneck. We demonstrated that 91.7% of edges require only 1 permutation for accurate null modeling, with the remaining edges requiring 2-3 permutations. This reduces storage requirements by approximately 99%, from 50 GB to less than 1 GB. More importantly, it reduces computational cost proportionally: instead of computing pathway counts across 200 permutations, we compute across 1-3 permutations.

This success illustrates the value of systematic analysis to identify and eliminate bottlenecks. What initially appeared to be a fundamental limitation (needing many permutations for stable estimates) was actually solvable through careful modeling with degree features.

### Pair Sampling: A Minor Issue

Sampling node pairs for training and testing incurs O(n²) cost to enumerate all possible pairs, but this is not currently limiting our analysis. For most metapaths, we sample 10,000-20,000 pairs from the millions of possible pairs, making sampling cost negligible compared to path counting. Random sampling is acceptable for our purposes, though stratified sampling (50% pairs with paths, 50% random pairs) provides better statistical properties.

The only scenario where pair sampling becomes expensive is when we need to identify all pairs with non-zero path counts in very dense metapaths. However, we can handle this efficiently using sparse matrix operations: the nonzero() method on a sparse matrix immediately returns all non-zero indices without explicitly checking every entry.

### Quantitative Impact Assessment

To prioritize our optimization efforts, we can quantify the relative impact of each bottleneck. Path counting for a single length-4 metapath takes approximately 6 minutes, and we need this for 1-3 permutations plus the original graph, totaling roughly 12-24 minutes per metapath. With dozens of metapaths of interest, this could accumulate to days of computation. If we extend to length-5 paths, the time would likely increase by another order of magnitude, making the analysis completely infeasible.

In contrast, matrix operations on large graphs might add seconds to minutes of overhead per analysis, and the permutation storage issue has been eliminated entirely. This makes the prioritization clear: solving the path counting bottleneck is essential for enabling length-5+ pathway analysis, while other bottlenecks are manageable with current methods.

## Priority 3: Strategies to Avoid Exhaustive Path Counting

### The Fundamental Challenge

Exhaustive path enumeration requires iterating over all possible paths of length L, which grows exponentially with L. Even optimized sparse matrix implementations cannot overcome this exponential growth. We therefore need fundamentally different approaches that avoid explicit enumeration while still providing accurate or approximate path counts.

### Strategy 1: Hierarchical Path Prediction (Primary Approach)

This strategy, tested in Priority 1, represents our primary approach to avoiding exhaustive enumeration. The core idea is to compute only short paths (length 2-3) directly using sparse matrix multiplication, which is feasible, and then predict longer path counts using trained machine learning models.

The computational savings would be substantial. Computing length-2 paths takes seconds, length-3 paths take minutes. Training a linear regression model on 10,000 samples takes milliseconds. Predicting path counts for millions of node pairs using the trained model takes seconds. In contrast, directly counting length-5+ paths would take hours or days and might not complete at all.

If this strategy succeeds, it transforms the problem from exponential to polynomial cost. We pay a one-time exponential cost to compute short paths, but then achieve constant-time prediction for long paths. This would enable analysis of pathways of arbitrary length, limited only by the accuracy of our predictive models rather than computational feasibility.

The key uncertainty is whether prediction accuracy remains high enough (r > 0.95) for paths of increasing length. If errors accumulate through recursive composition, the approach might work for length-4 or length-5 but fail for length-6+. However, even limited success would be valuable, as many biologically relevant pathways fall in the length-4 to length-6 range.

### Strategy 2: Sampling-Based Estimation

If hierarchical prediction fails or provides insufficient accuracy, sampling-based estimation offers an alternative approach. Instead of counting all paths exactly, we estimate path counts by sampling random walks through the network. For each source-target pair, we initiate K random walks from the source and count how many reach the target after exactly L steps.

The estimation quality improves with √K, meaning we need more samples for higher precision. For common paths with many possible routes, relatively few samples (K=1000) might suffice. However, rare paths would require many more samples (K=100,000+) to achieve stable estimates, making this approach most suitable for dense metapaths where most node pairs have at least a few paths.

Sampling-based estimation has cost O(K × L), which is linear in path length rather than exponential. This represents a massive improvement in scaling, though the constant factors might be large. The main limitation is that variance can be high for rare paths, leading to unreliable estimates for exactly the pathways that might be most biologically interesting (anomalies often correspond to rare events).

### Strategy 3: Degree-Conditioned Analytical Formulas

An alternative approach attempts to derive closed-form formulas for path counts conditioned on node degrees. This is analogous to our successful edge probability modeling but extended to paths. The formula might look like: Count(A→B→C→D | deg_A, deg_B, deg_C, deg_D) = f(degrees, graph_statistics).

The advantage of analytical formulas is that they provide instant predictions with zero computational cost beyond the initial formula derivation. However, deriving correct formulas is extremely challenging. Our previous attempts at analytical approaches (edge multiplication) failed because they couldn't capture the complex dependencies in real networks.

A potential approach would be to derive formulas based on random graph theory (e.g., configuration model assumptions) and then add empirical correction terms learned from data. This hybrid analytical-empirical approach might capture the main trends analytically while using machine learning to correct for systematic deviations in real biological networks.

### Strategy 4: Sparse Path Representation via Hubs

Biological networks often have hub nodes with very high degree that dominate path connectivity. Many paths flow through these hubs. We could potentially approximate path counts by only tracking paths that pass through the top K highest-degree nodes, treating them as required waypoints.

For example, if we identify the top 100 genes by degree, we might assume that most Compound-Disease paths of interest pass through at least one of these genes. We could then enumerate only paths of the form C→hub1→...→hub2→D, which would be much faster than enumerating all possible intermediate paths.

The main limitation is that this approach misses paths through low-degree nodes, which might be important for specific compound-disease pairs. However, for anomaly detection focused on finding unusually high path counts, we might only care about common paths through hubs anyway, making this approximation acceptable for our use case.

### Strategy 5: Path Binning and Extrapolation

Another approximate approach involves counting paths for only a sample of node pairs (say 10,000 pairs) and then extrapolating to estimate total path counts across all pairs. We would bin pairs by their degree signatures and use the empirical distribution within each bin to estimate counts for uncounted pairs.

This approach works well if path count distributions are regular and predictable within degree bins. The computational cost is O(n_sample × exp(L)), which could be much smaller than counting for all pairs if n_sample << n². However, for pair-specific anomaly detection, we ultimately need counts for specific pairs, not just distributional estimates, limiting the applicability of this approach to our goals.

### Recommended Integration Strategy

Our recommended approach integrates multiple strategies based on the specific requirements of each analysis. For paths of length 2-3, we use direct counting (Strategy: matrix multiplication) as it is fast and exact. For paths of length 4-5, we test hierarchical prediction (Strategy 1) first, falling back to sampling (Strategy 2) if prediction accuracy is insufficient. For paths of length 6+, we accept approximate methods (sampling or hub-based) as exact counting is infeasible regardless of approach.

This tiered strategy maximizes accuracy where possible while maintaining computational feasibility across all path lengths. It also allows us to trade accuracy for speed based on the specific research question: exploratory analyses might accept approximations, while validating specific biological hypotheses might require exact counts for shorter paths.

## Priority 4: Anomaly Detection Pipeline Architecture

### The End Goal

Our ultimate objective is to identify biologically unusual pathways in Hetionet by comparing observed path counts to null distribution expectations. Anomalies might represent novel therapeutic relationships, incorrectly annotated pathways, or interesting biological phenomena worthy of experimental validation. The pipeline must be accurate enough to identify true biological signals while being computationally efficient enough to run across thousands of metapaths and millions of node pairs.

### The Scalability Challenge

Consider the CtDaG metapath (Compound→treats→Disease→associates→Gene). With approximately 1,552 compounds, 137 diseases, and 20,945 genes, there are roughly 1,552 × 137 ≈ 212,624 possible compound-disease pairs to analyze (after the first two edges). Even if only 10% have non-zero pathway counts, that's 21,000 pairs. Computing pathway counts across multiple permutations for 21,000 pairs, then training models and computing z-scores, adds up quickly.

The solution is to leverage sparse matrix operations to identify only the non-zero pathways in the real graph, then focus our computational effort on just those pairs. Most node pair combinations in biological networks have zero connectivity, so this typically reduces the problem size by 90-99%. For sparse metapaths like CtDaG, we might have only 1,000-5,000 non-zero pairs rather than 200,000+ possible pairs.

### Recommended Workflow

The anomaly detection pipeline will operate in five main stages. First, we compute observed pathway counts in the real Hetionet graph using sparse matrix multiplication. This gives us a sparse matrix where most entries are zero, and we extract only the non-zero entries as our candidate anomalies.

Second, we determine how many permutations are needed using yesterday's heuristic based on bottleneck edge counts. For metapaths with all edges above 1,000 edge count, we use 1 permutation. For metapaths with smaller bottleneck edges, we use 2-3 permutations. This ensures we have sufficient data for stable null distribution estimates while minimizing computational cost.

Third, we compute pathway counts in the permuted graphs, but only for the specific node pairs that had non-zero counts in the real graph. This is much faster than computing for all possible pairs. We use these permutation counts to train a degree-based model that predicts expected counts from node degrees, and we estimate variance empirically from the permutation variation.

Fourth, we compute z-scores for each node pair: z = (observed - expected) / sqrt(variance). Pairs with |z| > 3 are flagged as anomalies, corresponding to roughly 99.7% confidence under normal assumptions. We rank all pairs by absolute z-score to identify the strongest anomalies.

Fifth, we validate and interpret the anomalies. We check whether high-z-score pairs correspond to known biological relationships documented in the literature. We enumerate the actual paths (not just counts) for the top anomalies to understand the mechanisms. We look for patterns such as enrichment of specific drug classes, diseases, or biological processes among the anomalies.

### Handling Long Paths

For anomaly detection on long paths (length 5+), we have three options depending on the success of our hierarchical prediction experiments. If hierarchical prediction works (r > 0.95), we simply compute short subpath counts and predict long path counts using trained models. This is fast and accurate.

If hierarchical prediction provides moderate accuracy (0.8 < r < 0.95), we might use it as a first-pass filter to identify candidate anomalies, then apply more expensive exact counting methods only to the top candidates. This hybrid approach combines computational efficiency with accuracy where it matters most.

If hierarchical prediction fails entirely, we fall back to sampling-based estimation for long paths. We accept that path count estimates will have higher uncertainty and adjust our anomaly detection thresholds accordingly. We might focus anomaly detection on shorter paths (length 2-4) where we can achieve exact counts, treating longer paths as exploratory rather than definitive.

### Validation Strategy

To ensure our anomaly detection pipeline produces meaningful results, we will validate against known biology. For example, we will check whether aspirin-cardiovascular disease pathways show high pathway counts (positive anomalies), confirming that the method detects known therapeutic relationships. We will also check for false positives by examining whether random or biologically implausible pairs are flagged as anomalies.

We will compare anomaly scores to external data sources such as clinical trial databases, drug repurposing predictions from other methods, and literature co-occurrence statistics. High-quality anomalies should correspond to known or plausible biological relationships, while low-quality anomalies might reflect data quality issues or methodological artifacts.

The validation step is essential because anomaly detection methods can easily produce spurious results if not carefully calibrated. Statistical anomalies (high z-scores) must correspond to biological anomalies (interesting relationships) for the method to be useful. We will iterate on the method until we achieve good concordance between statistical and biological significance.
